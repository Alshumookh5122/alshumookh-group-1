Official technical submission guide for senders preparing JSON transfer files for master-wallet-to-master-wallet settlement with ALSHUMOOKH GLOBAL BANKING FINANCE & CREDIT.

Document Type Technical Integration Workflow
Transfer Type MASTER_WALLET_TO_MASTER_WALLET
Environment Production
This document describes the required JSON file structure, upload workflow, validation rules, supported assets, and final confirmation requirements.

1. Purpose

This workflow is used when the sender prepares a batch transfer file in JSON format and uploads it to ALSHUMOOKH system for validation, operational review, and settlement tracking.

Transfer type must be exactly: MASTER_WALLET_TO_MASTER_WALLET

2. File Requirements

Item Requirement
File Type .json
Encoding UTF-8
One File Per Batch Each JSON file must represent one transfer batch only.
Duplicate Batch ID Duplicate batch_id values may be rejected.

7. Upload and Processing Workflow

  1. Prepare the JSON file according to the structure in this document.
  2. Validate the JSON syntax before upload.
  3. Upload the JSON file to ALSHUMOOKH system.
  4. Wait for file validation and operational review.
  5. If accepted, proceed with blockchain transfer.
  6. Submit or update the transaction hash after sending funds.
  7. ALSHUMOOKH confirms after wallet, token, amount, and transaction hash verification.

8. Status Flow

Status Meaning
UPLOADEDFile has been uploaded to the system.
VALIDATION_PENDINGFile is waiting for validation.
VALIDATEDFile passed required validation checks.
REJECTEDFile failed validation or operational review.
PENDING_TRANSFERSender is expected to initiate transfer.
TRANSFER_SUBMITTEDSender submitted transaction hash.
CONFIRMEDBlockchain transaction has been matched.
COMPLETEDFinal settlement is accepted by ALSHUMOOKH.
FAILEDTransfer failed, mismatched, or cannot be accepted.
Final settlement is valid only when ALSHUMOOKH marks the transfer status as COMPLETED.

9. Rejection Reasons

  • Invalid JSON format.
  • Missing required fields.
  • Wrong destination wallet address.
  • Wrong network.
  • Unsupported token or fake token contract.
  • Amount mismatch.
  • Duplicate batch ID.
  • Missing sender declaration.
  • Invalid or unmatched transaction hash.

11. Security Rules

The sender must not request or receive:

  • Admin API Key
  • Private keys
  • Database credentials
  • Webhook secrets
  • Treasury wallet private keys

Only public wallet addresses, payment references, and transaction hashes may be shared for operational matching.
